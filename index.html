Build your first M365 reporting flow

Start with the recipe card for its exact method, API host, permission, output format, and flow-specific steps. API families differ, so don’t assume every response is JSON or every service uses Microsoft Graph.

1 · Choose the matching API

  1. Microsoft Graph usage reports use graph.microsoft.com/v1.0 and require Reports.Read.All. The Copilot report is under /copilot/reports/.
  2. Those report endpoints return CSV; some respond with a short-lived download redirect. They are not regular JSON value collections.
  3. Power Platform inventory uses api.powerplatform.com, not Graph, and requires delegated user authentication.

2 · Prepare authentication

  1. In Power Automate, create a scheduled cloud flow and add an approved HTTP action or custom connector.
  2. For Graph app-only recipes, add only the documented Application permission to the app registration and have an admin grant consent.
  3. Store credentials in an approved secure connection or vault; never place secrets in a URL, flow output, or report.

3 · Handle and protect the report

  1. Use the recipe’s exact HTTP method and copy its full request. Graph report CSV needs CSV-aware handling; don’t use Parse JSON on it.
  2. For Power Platform inventory, send the documented JSON query body using delegated authentication and handle its paging token.
  3. Minimize user-level data, restrict run-history access and recipients, and verify licensing, cloud availability, retention, and tenant policy.
